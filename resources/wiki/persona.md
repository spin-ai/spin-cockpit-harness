# 人物画像

> 记忆存的是「发生过什么」，画像存的是「这个人是什么样、什么时候会变」。
>
> 上下文窗口再大也不是记忆。上下文是缓冲区，画像是**对显著信息的结构化保留和对噪声的主动遗忘**。

## 数据分三层，不要混

| 层 | 存什么 | 落盘 | 谁在读 |
|---|---|---|---|
| 会话 | 原始消息、事件、run | `harness.db` + `memory/mem.db` 的 transcript 索引 | `memory_search`（只读回查） |
| 人物 | 当前成立的事实、可观测特征、关系 | `persona/persona.db` | 人物页、`persona_lookup` |
| 记忆 | L1–L4 结论、未验证观察 | `memory/mem.db` | 注入进 run 的记忆块 |

三层独立：删掉 `persona.db` 只是重建画像，不会丢聊天记录。

## 能回答与不能回答

**能**：他大概会怎么反应、这事该找谁、这句话像不像他说的、他以前是什么样（按时间回看）。

**不能**：心理诊断、身份猜测、以及**任何没有原话支撑的判断** —— 没证据就返回「未知」并摊开可用关系，不猜。

## 四种「忘」是四个不同操作

混用会直接损害画像一致性 —— 这是这类系统最容易出错的地方。

| 操作 | 触发 | 结果 | 判据 |
|---|---|---|---|
| **失效 invalidate** | 单值字段（身份 / 角色 / 处境 / 价值观 / 目标）来了新说法 | 旧值写 `valid_to = 新值 valid_from`，不删除；回看/漂移里仍可查 | 两个方向都处理，先确认新的再确认旧的也不会写反 |
| **衰减 decay** | 时间流逝 | `heat = confidence × 2^(-天数/半衰期) × log2(2+证据量)`，只在读时算 | 事件 7 天、承诺 21 天、说话风格 60 天、性格 180 天、身份/价值观 730 天 |
| **到期 stale** | 时间敏感事实（事件 / 承诺 / 硬约束）过了 `expires_at` | 标 `stale` 进复核队列，不进卡片与注入，**不删除** | 到期时间先从原话里读（下周 / 月底 / 明年），读不到用字段默认 TTL |
| **合并 merge** | 两条在说同一件事 | 证据累加到保留项，旧值标 `merged`，不删 | 归一化后完全相同自动合；近似值（bigram ≥ 0.6）只出建议，人确认才合 |

再加一条不是「忘」而是「逢出视野」的：**检索上限 evict** —— 多值字段在卡片里只展示 `heat` 最高的 N 条（语气样本 3、说话习惯 8、事件 10），其余留在库里当证据，热度回升就能再上来。把超出上限的直接标 expired 会把复核队列灌成几百条，人就不会再去清它。

## 记什么：数得出来的不进事实层

- **measure（可观测特征）**：话量、句长、接话时延、群/私聊比、活跃时段、高频词、笑声/表情/省略号比例……
  重算即可，进 `measures` 表，只留最新值 + 上一次值 + 变化次数。
- **belief（事实）**：身份、角色、偏好、约束、处事方式、说话风格 —— 重算不出来，需要人确认。

为什么必须分开：一次建模算出「群聊 0% / 私聊 100%」，下次样本变了算出 1% / 99%，如果两条都叫「事实」，失效永远追不上重算，画像里会堆满同时成立的矛盾值。

## 证据是「次数」，不是「条数」

- 同一事实再次被观察到 → `evidence_count + 1`、`confidence + 0.03`（封顶 0.95）、`last_seen_at` 推进。
  **不是**「去重后丢掉第二条」—— 否则「50 次对话印证过的一句话」和「模型一次猜测」在画像里强度完全一样。
- 卡片里的「依据 N 条」是证据次数；`supportMedian` 恒为 1 就说明记忆还没在累积。
- 建模给的引用会**回查**：模型说「原话是 X」，X 必须在它当时看到的样本里能核对上；核不到标「引用待核对」并降权 0.6 —— 不删、不拦，交给人在确认前对一下。
- 拒绝不是永久事实：同类事实又独立观察到两次（或距上次拒绝超 120 天）会复审一次；再拒绝后计数归零，不会反复打扰。

## 时间轴是两条

- **事件时间**：那个时间点什么是真的（`valid_from ≤ at < valid_to`）
- **认知时间**：系统在那个时间点已经知道什么（`created_at ≤ at`）

2024 年发生、2026 年才得知的事，在 2024 年的「当时已知」里不该出现。人物页右栏可以切换这两种口径。

## 建模怎么跑才值

1. **先只跑统计**（「只跑统计」不花钱）：先看这个人有没有可说的行为面，再决定要不要花模型调用。
2. **模型只补可数不出来的东西**：身份线索、价值取向、目标、决策习惯 —— 统计给不了这些。
3. **每人一次调用 + 2 路并发 + 90s 超时**；每个请求挂自己的 `AbortController`，取消立刻释放连接。
4. **缓存按 `(契约版本 | 模型 | 人 | 样本)` 的 sha1**：同一份样本不重复花钱。只有「真的产出了非空结论」才写缓存 —— 否则模型换输出结构时写出一条空缓存，之后同一份样本永远跳过，卡片永远只有统计。
5. **缺 key 直接报错**，不要静默跑完显示「0 人出卡」。
6. 跑完顺手扫一次到期事实（标 `stale`），复核队列不会空着当摆设。

## 踩过的坑（都是真踩过的）

| 现象 | 根因 | 现在的做法 |
|---|---|---|
| 全库 `valid_to` 一条都没有，同一字段同时成立好几种说法 | 统计结论直插 `confirmed`，绕过失效逻辑 | 可观测特征进 `measures`；写入只有一条闸门 |
| 「50 次印证」和「一次猜测」强度一样 | 去重命中后 `return null`，证据被丢掉 | 累加 `evidence_count` |
| 注入里全是语气样本，处事方式被挤掉 | 按固定字段顺序硬截，而库里 73% 是 voice/style | 按 `字段优先级 × heat × 问题相关性` 打分填预算，每节配额上限 |
| 拒绝过的事实永不再提 | `rejects` 是永久静音 | 攒够两次独立观察 / 超 120 天复审一次 |
| 人物卡顶端的一句话三个月没人动 | 生成后从不重算 | 记 `one_liner_at`，之后有新事实/新统计就提示重写（确认待确认不算新结论） |
| 建模跑完「0 人出卡」却一条错误不报 | 只读进程环境变量，从 Finder 启动没有 `ARK_API_KEY` | 走设置里的 key，缺 key 直接抛错并指路 |
| 问「他会怎么反应」返回一串随机引文 | 中文 2-gram 下「这个 / 今天 / 同意」到处命中，命中一个就算依据 | 要求问题原词（≥3 字）原样命中，或 ≥2 个词命中且 df 加权够高 |
| 合并完两个人，用旧名字叫不动了 | 点名只认 `name`，不认 `aliases` | 名字与别名任一命中 |

## Agent 侧怎么用

- **`persona_lookup`**：问「他会怎么反应 / 该找谁 / 影响谁」，返回带来源的结论；没依据返回 `found:false`。
- **`persona_review`**：列出需要复核的到期事实（不注入、不计入现状）。
- **任务里点名会自动带上画像**：标题 / 描述 / 补充指令里出现联系人名字（≥2 字，含合并前的旧名字）时，注入 ≤600 字片段，最多 3 人；没点名一个字都不注入。
- **敏感项永不进人物卡、永不进注入**，只报数量。
