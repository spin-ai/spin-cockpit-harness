# 记忆与 Dream

> 记忆管「层次与流动」，知识库管「对象与检索」，人物画像管「这个人随时间什么是真的」。三件事三套库，互不写入。

*图：记忆页：结论 / 来源 / 复核并列，右侧是 Dream 建议与注入预算。*

## 四层

```text
L1 Transcripts  →  L2 Memory Notes  →  L3 知识（资料 + 页面）  →  L4 Injected
       ↑                    ↑                    ↑                    ↑
        └────────────── Dream：校正 / 构建 / 补洞 / 晋升 / 剪枝 ─────┘
```

| 层 | 放什么 | 谁能写 | 怎么读 |
|---|---|---|---|
| **L1 Transcripts** | 会话消息、run、工具调用、事件 | 只有系统（不可变） | `memory_search` / `run_read`，只读回查 |
| **L2 Memory Notes** | 显著观察、未验证猜测、踩过的坑 | Agent 写，人标 verified | `note_search`，可错、可过期 |
| **L3 知识** | 资料（只读）+ 页面（可审核） | 导入 / 人写 / Agent 写 draft | `kb_search` / `kb_read` |
| **L4 Injected** | 每次会话预加载的目录，≤12k 字符 | Dream + 人 | 自动注入 |

四条硬规则：

1. **越高层越小**：L4 是目录，不是书；
2. 上层只能**引用**下层，不复制正文；
3. 每条内容都必须能回答「从哪来的」（`source_kind + source_id` 必填）；
4. L1 不可变——否则 Dream 的 ground truth 就失效了。

## 四种「忘」不是一件事

混用会直接损害一致性，所以每个动作对应各自的字段与入口：

| 操作 | 语义 | 写什么 | 可回看 |
|---|---|---|---|
| **失效 invalidate** | 事实被推翻 | `invalid_at` + `superseded_by`，不删行 | ✅ `entryAsOf()` |
| **衰减 decay** | 自然过期 | note 的 `expires_at`（rule / decision 不过期，guess 14 天） | ✅ 行还在 |
| **淘汰 evict** | 用不上 / 超体积 | `status = archived` | ✅ 可恢复 |
| **合并 merge** | 两条在说同一件事 | 新条目 + 两条 `superseded_by` | ✅ |

两条底线：**失效永远不删行**；**人验证过的 note 清掉 `expires_at`**，不再自动遗忘。
人物画像还有一套自己的「四种忘」，语义与字段都不同，见 [人物画像与记忆语义](#/wiki/persona)。

## L1：索引可删可重建

- 消息与事件进 `mem.db` 的 `transcript_fts`，统一走 **bigram**（中文两字词在 `unicode61` / `trigram` 下查不到）。
- `transcript_map` 存 `(kind, ref_id) → rowid`：改写消息先删后插，不留旧文本。
- 写入时同步索引，钩子包 try/catch——**索引失败不能弄坏业务写入**。
- 启动对账清孤儿、补缺失；FTS5 不可用就回落内存扫描，不把整个记忆层带崩。
- 片段切在命中词附近（自己算 snippet），因为索引的是 bigram、原文是另一列。

## L2：允许写错，但必须能追责

- 没有 `source_ref` 直接拒绝，`manual` 也要写清谁写的。
- 一条观察不超过 400 字符；超了应该去写页面 / 条目，而不是塞进 note。
- 同一句话只存一行：正文去空白与标点后哈希做键，重复写入只抬置信度。
- 改写留旧版（`note_revisions`）——Dream 记错一次必须能回退。
- 不进入页面审核流，也不计入 `reviewed`。

## L4：打分注入，不按字段顺序硬截

```text
分数 = 置顶 + 有来源 + 层级 + 近两周 + log(被用过)
```

- 每节有配额上限（处事 / 性格 / 声音 / 基本信息 / 事实），分节标题也计入预算。
- `inject_log` 记录每次 run 注入了哪些 id、是否被回答用到，回填 `hit_count`，用来算命中率。
- 归因很粗：按标题片段是否出现在回答里判断，只能区分「从没被用过」。

## Dream：只提议，不自动改

七类确定性检查轮询 L1–L3，产出**建议队列**，不是直接改写：

- 换说法的重复、已不成立的结论、该改写的糙句；
- 补洞（缺来源）、晋升（note → 条目）、剪枝（过期 / 冲突）；
- 每日有建议预算，避免一次刷出几百条没人看。

每条建议带三样东西：**逐行 `-`/`+` 的 diff**（会改掉什么）、**`base_rev`**（基于哪一版）、**`confidence`**（1 = 确定性检查，0.5 = 模型判断）。

接受前会校验目标版本：如果目标在这条建议之后被改过（人改的，或另一条建议改的），建议直接标 `superseded` 作废，**不会覆盖人的修改**；作废也不等于「人拒绝了它」，不进 `rejects`。

语义 pass（模型）默认关闭；打开后一次调用找「重复 / 已不成立 / 糙句」。它拿到的不是一句结论，而是**观察自己的出处原文**（回 L1 索引取）+ 相关会话片段 + 页面引用原句——没有证据就不许报 `correct`。但**仍然没有准确率数据**，属于使用者自己承担的实验项。

Dream 是循环而不是按钮：应用空闲（`idleMinutes`，默认 30 分钟、没有 run 在跑）会自己跑一轮；输入指纹没变就跳过（不扫描、不调模型）；每轮写进 `dream_runs` 台账，记忆页能看到「上次 空闲 · 2 小时前 · 3 条 · 1s」。
晋升有三道边界：`stale / rejected` 不能晋升、过期结论不能进 L4、`source_ref` 必须非空。

## 边界

- 与人像记忆**互不写入，不共用检索入口**：`persona_lookup` 回答「这个人」，`memory_search` 回答「哪次提过」。
- 与知识库分工：记忆管层次与流动，[知识库](#/wiki/knowledge)管资料 / 页面与检索。
- L1、`mem.db`、`kb.db` 都可重建；`harness.db` 才是唯一事实源。

## 明确未做

- 注入归因只到「标题片段匹配」，还不能回答「这条记忆改变了哪一步回答」。
- Dream 的语义 pass 没有准确率评估；合并建议仍需要人确认才落盘。
