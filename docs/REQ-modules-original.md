# 原始需求 · 按模块

> 状态：原始记录，待逐条确认。只写“想要什么”和少量现状，不展开实现细节。

## 0. 产品一句话

一个本地优先的控制面，把执行、编排与知识沉淀收进同一套状态，Agent 走向可观察、可审批、可记忆 。

- 多 Agent 工作台：Chat 派活，Agent 在真实项目和终端执行，TODO 看状态，人确认。
- Super Agent：复杂可并行任务才拆主管—子任务，计划先批、结果再汇总。
- LLM Wiki：分层记忆沉淀可审核页面，后台去重、补引用、标过期。

## 1. 场景工作台

> 目标：一个页面管住所有项目、终端和执行配置；Chat 负责派活，TODO / Chat 负责看进展。

### US-1 场景总览与配置

**作为** 同时维护多个项目的开发者  
**我希望** 在一个页面看到所有已打开项目、项目内终端，并用文字编辑场景配置  
**以便** 统一管理执行环境、Agent 和进展，不用逐个项目切换

**验收**

- 项目、项目内终端、运行状态全部可见
- 文字配置可保存，并在下一次派活生效
- 能看出每个项目的运行中、待确认和异常终端
- 场景配置能决定任务分配给哪个项目、哪个 Agent、用 ACP 还是终端

### US-2 全局进展

**作为** 用户  
**我希望** Chat 和 TODO 都能看到所有项目、所有终端的执行状态  
**以便** 随时知道哪个 Agent 在跑、卡住或待确认

**验收**

- Chat 可切换「当前会话 / 当前项目 / 所有项目」
- TODO 聚合所有项目，而不是只看当前项目
- 终端运行、等输入、已退出状态与任务状态一致

### US-3 终端优先启动 Agent

**作为** 想快速开工的用户  
**我希望** 打开项目终端后直接启动 pi Agent，并让它进入统一进展  
**以便** 先跑起来，再决定是否绑定任务

**验收**

- 终端启动的 Agent 能被统一视图识别
- 能看到运行时长、最近输出、退出码
- 可后续接入某个任务

### US-4 一个任务多个可见 Agent

**作为** 任务负责人  
**我希望** 一个任务能同时派给多个 Agent，且每个 Agent 都有独立可见的终端  
**以便** 我盯着每个执行过程，而不是看不见的 Agent 在跑

**验收**

- 每个 Agent 一个终端标签或窗格
- 任务与终端可互相跳转
- 每个 Agent 可单独停止、纠偏、确认

### US-5 按场景自动分配

**作为** 用户  
**我希望** Chat 聊完并确认执行后，系统按场景配置推荐并分配项目、Agent 和执行方式  
**以便** 少做重复配置，又不失去控制

**验收**

- 分配前显示建议和理由
- 人确认后才创建任务和运行
- 可手动改项目、Agent、执行方式

### US-6 统一任务模型

**作为** 用户  
**我希望** Mission 只是 TODO 中的一种任务，Terminal 是任务的执行现场  
**以便** 不用在 Mission、TODO、终端三套页面和状态之间切换

**验收**

- Mission 出现在 TODO 列表 / 看板中
- Mission 卡片可展开子任务
- 任务行能定位到对应终端，状态一致

**当前**

- 已有项目页、终端标签、TODO 看板、统计；没有场景配置对象。
- 终端标签没有按项目持久化和总览。
- Chat 只能看当前会话。
- Chat 的终端模式已经能自动开终端运行 pi 等 CLI；但「先开终端、再起 Agent」还没有接入任务和进展。

**待确认**

*场景配置*

1. 场景配置是每个项目一份，还是一个项目可以有多份？
2. 「文字修改」是只写备注，还是要能直接驱动自动分配？
3. 自动分配是直接开跑，还是先给建议、人确认后再跑？
4. 先做只读总览，还是直接做可编辑配置？

*终端与多 Agent*

5. 「先开终端、再起 Agent」的方式，Agent 要不要被 harness 识别成一个可管理的运行？
6. 没有绑定任务的 Agent，算不算「进展」？
7. 一个任务多个 Agent，用 Mission 承接，还是普通 TODO 直接并行？
8. 多个 Agent 是多个终端标签，还是同一个终端里分屏？
9. 「先开 terminal 再起 pi」的 Agent，如何和这个任务绑定？
10. 一个任务需要多个 Agent 时，是否允许自动开多个终端？
11. TODO 里的「终端执行状态」具体指什么：命令在跑、Agent 在跑、等输入、已退出，还是全部？

*全局进展*

12. 统一看状态的地方在哪里：场景配置页、Chat，还是两边都有？
13. Chat 的「所有进展」包括哪些：所有项目、所有终端、所有运行、所有待确认？

## 2. 项目 / 工作区

**原始需求**

- 项目 = 本地目录；一个目录一个项目。
- 支持添加、切换、重命名、状态、移除。
- 任务、终端、文件树跟随当前项目。
- 项目有唯一 `@别名`，用于 Chat 路由。
- 项目是 Agent 执行和 worktree 的边界。

**当前**

- 已实现项目增删改查、切换、状态、别名、文件树跟随。
- 项目页支持重命名、Finder、移除。
- 没有项目级场景配置。

**待确认**

- 项目页要不要变成“项目 + 场景 + 终端 + 进展”的总览？
- 是否支持项目分组 / 排序 / 收藏？

## 3. TODO / 任务

**原始需求**

- 一条任务列表，按状态分组：待执行 / 运行中 / 等待输入 / 待确认 / 已确认。
- 任务字段：标题、描述、验收、优先级、截止、标签、项目、Agent。
- 行内操作：编辑、派活、停止、确认、重试。
- 点任务同步 Chat 和 Terminal。
- 确认是状态，不产生第二份数据。

**当前**

- 已实现状态分组、搜索、筛选、行内编辑、派活/停止/确认/重试。
- Mission 也作为任务卡片出现在 TODO。
- 任务行显示项目、Agent、耗时、终端状态（部分）。

**待确认**

- 一个任务是否允许多个 Agent 并行？
- 确认后是否允许撤销？
- 是否需要横向看板视图，还是保持分组列表？

## 4. Mission / Super Agent

**原始需求**

- 一个目标拆成多个子任务，由主管统一推进。
- 计划必须先由人批准。
- 子任务有独立 Todo / Run / worktree，可以单独暂停、确认、取消。
- 主管只读，worker 才改代码。
- Mission 完成必须由人确认。
- 失败、取消、重启不能伪造完成。

**当前**

- 已实现本地 Mission：Plan / Delegation / Supervisor / MCP 工具 / 计划审批 / 事件回灌 / 取消级联 / 重启恢复。
- supervisor 强制 ACP。
- Mission 卡片在 TODO 看板里展示子任务进度。

**待确认**

- 一个任务多个 Agent 时，是否都用 Mission 承接？
- 终端 Agent 是否可以作为 Mission 的 child？
- 是否做远程 supervisor / 多层主管？

## 5. Chat

**原始需求**

- Chat 是唯一分派入口。
- 会话（thread）是消息宿主，不绑任务也能存在。
- 一句话派活；运行中继续说话 = 纠偏。
- 纠偏有投递回执：投递中 / 已注入 / 失败重发。
- 支持 `@别名` 指定项目 / Agent。
- 支持元素上下文注入。
- 任务确认后消息只记录。

**当前**

- 已实现 thread、单一 `send` 路径、纠偏回执、@别名、元素上下文、命令、会话历史、输入历史。
- 普通消息默认派活；`@别名` 用来指定目标。
- Chat 目前只看当前会话，没有全局进展视图。

**待确认**

- Chat 是否要做“所有项目”进展 dock？
- 是否支持多 Agent 广播？
- 是否要做不绑任务的纯聊天 / 常驻 ACP 会话？

## 6. Terminal

**原始需求**

- 真实 pty，不是日志窗口。
- 任务绑定项目目录，Agent 在终端里启动并登录。
- 多标签、可直接输入、可拆分。
- 终端输出就是进展。
- 运行中直接在终端输入，也能纠偏当前 Agent。
- Chat 派活和终端执行要能互相对应。

**当前**

- 已实现真实 pty、多标签、拆分、查找、右键菜单、链接、字号、重启、挂载前回放。
- Chat 的终端模式会自动开终端、启动 pi 等 CLI，并把后续消息写回同一个 pty。
- 终端标签目前是 renderer 内存状态，没有按项目持久化 / 总览。
- 终端里手动起的 Agent 还没有“接入任务”流程。

**待确认**

- 是否支持“先开终端、再起 Agent”，并纳入统一进展？
- 一个任务多个 Agent，是否多个终端标签 / 窗格？
- 终端优先的 Agent 如何绑定 worktree 和任务？

## 7. 预览 / UI 上下文

**原始需求**

- 预览是终端里的一个标签，不打断 pty。
- 终端打印的 dev server 地址能自动识别。
- 预览里能点选元素，把 selector / 样式 / 源码位置 / 截图注入 Chat。
- 支持本地 HTML 预览与可视化编辑。
- 页面切换 / 源码切换不丢状态。

**当前**

- 已实现预览标签、dev server 识别、元素拾取、源码定位、HTML 可视化（GrapesJS）、Markdown 预览、源码编辑保存。
- 预览支持刷新、拾取、Finder、复制路径。

**待确认**

- 是否需要更完整的浏览器操作：前进/后退、设备宽度、缩放、页内查找、DevTools？
- 是否需要同时打开多个预览页？

## 9. LLM Wiki / Notes

**原始需求**

- 原生 Wiki，不是 Obsidian vault 浏览器。
- Source → Page → Citation → Review → Revision。
- Agent 只能写 draft；reviewed 页面不能静默覆盖。
- 支持本地 Markdown 目录导入 / 编辑 / 写回。
- 支持 Memory 索引、搜索、图谱、Review 队列。
- 通过 MCP 工具让 Agent 检索和写 draft。

**当前**

- 已实现 Notes 插件、Source/Page/Citation/Review/Revision、Memory、Dream、图谱、CodeMirror 编辑器、MCP 工具。
- 支持本地 Markdown 目录导入、页面编辑、审核。

**待确认**

- 是否需要 PDF / 网页剪藏等更多 Source？
- 是否需要更深的 LLM 维护（自动合并、过期检测）？

## 10. Agent / 主机 / 执行方式

**原始需求**

- Agent = CLI + 主机 + cwd + 别名 + 并发上限。
- 支持本机与 SSH 主机；能探测 CLI / 版本 / git / 目录。
- Chat 执行方式按 CLI 选择：dsh 走 ACP，pi / claude / codex / opencode 走终端 pty。
- 不支持的 CLI 明确报错，不静默换引擎。
- 并发、审批、失败分类可见。

**当前**

- 已实现 Agent 纳管、本机/SSH 主机探测、心跳、并发、审批、错误分类。
- dsh ACP 与终端 pty 两种执行方式已接入 Chat。
- Mission 强制 ACP。

**待确认**

- 是否需要更多 CLI 的 Chat 执行适配器？
- 是否需要 Runtime = 主机 + CLI + caps 的独立对象？
- 是否需要账号额度 / 用量治理？
