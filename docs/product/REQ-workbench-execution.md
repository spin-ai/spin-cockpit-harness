# 工作台任务与执行体验需求

> 设计回答见 [`../arch/ARCH-workbench-execution.md`](../arch/ARCH-workbench-execution.md)。
> 本文先锁定用户能做什么、做完看到什么；不以当前实现的隐藏任务或终端补丁反推需求。

## 1. 要解决的问题

当前产品同时存在几种说不清的状态：

- 从终端启动 Agent 后，任务列表没有它；关闭标签后又找不到它。
- 把手动 Agent 终端「接入任务」会补建一条正在运行的 Run，但 Harness 并不知道它真实的启动时间和完成边界。
- 纯聊天为了不违反「Run 必须有 Todo」，创建了不在看板显示的隐藏 Todo。
- 关闭终端标签同时意味着「不再查看」和「取消执行」，用户因此不敢关标签。
- Chat、任务面板、终端、Mission、IM 都能起执行，但确认时机和产出的对象不一致。

目标不是再增加一个会话列表，而是让用户始终能回答四个问题：

1. **这是一件要验收的工作，还是一次探索？**
2. **这次是 Harness 受管执行，还是我手动使用终端？**
3. **这句话或这个进程属于哪个项目、哪个任务？**
4. **关闭标签只是不看，还是真的停止？**

## 2. 产品原则

1. **Project 是归属，Todo 是工作，Run 是受管执行，Terminal 是进程，Thread 是对话，Tab 只是视图。** 六者不互相冒充。
2. **任务中心不变**：左栏只放任务与项目，不放第二份 Terminal / Thread 列表。
3. **探索是一等状态**：可以先执行、先聊天，之后再转成任务；不为了看板完整而自动制造任务。
4. **受管与手动必须诚实**：Harness 启动并跟踪的执行才是 Run；用户在 shell 里手敲 `pi` 不自动补 Run。
5. **看 ≠ 停**：关闭标签只关闭视图；停止 Run、结束进程都是独立且明确的动作。
6. **同一来源只有一种任务形状**：入口可以很多，任务模型、执行记录和确认规则不能随入口变化。
7. **历史归属不被界面动作改写**：取消任务、关闭标签、切换项目都不删除或伪造执行历史。

## 3. 用户故事与验收

### US-01：从任务面板派活

> 作为用户，我新建或选中一条任务、选择 Agent 后点「派活」，希望立即看到这次执行，而不必理解 ACP 或 pty。

**验收**

- 「派活」前先存在一条真实 Todo；点击后只创建一个新 Run。
- Agent 的默认执行方式决定打开对话面还是终端面，用户不再选一次「终端派活」。
- 对话型执行没有 Terminal；终端型执行有且只有一个绑定 Terminal。
- 执行状态、耗时、结果回到原 Todo；重试产生新 Run，不覆盖旧 Run。

### US-02：先打开 Agent 探索，再决定是否成为任务

> 作为用户，我想从标签栏直接打开一个 Agent 终端做探索，一开始不填任务表单；如果这次探索值得跟踪，再把它关联到任务。

**验收**

- 从「＋ → 打开 Agent 终端」启动时，Harness 创建一条**没有 Todo 的受管探索 Run**，并打开原生终端标签。
- 它必须属于当前 Project；左栏不会自动多出任务。
- 选择「关联到现有任务」或「建成任务并关联」后，沿用原 Run 的 id、启动时间、输出与退出状态，不新造 Run。
- 若关联时 Run 仍在执行，任务显示执行中；若已完成，任务进入结果审阅；若失败，任务显示失败且可重试。
- 不同 Project 的探索 Run 不能静默关联到当前任务。

### US-03：照常打开 shell、手敲 pi

> 作为用户，我希望「新建终端 → 输入 pi」永远可用，而且不被系统擅自转成任务或受管执行。

**验收**

- 新建 shell、在 shell 里手敲 `pi` / `claude` / `codex`，只产生 Terminal，不产生 Run 或 Todo。
- 用户可以把这个手动终端关联到任务，便于从任务详情找回；关联后 **Run 数量不变，Todo 状态不被自动改成进行中**。
- 任务详情明确标注「手动终端」，不显示伪造的 Run 耗时、退出码或「已注入」回执。
- 对没有受管 Run 的手动终端，Chat 不提供虚假的「停止本次 Run」或「纠偏已注入」。

### US-04：关闭标签后仍能找回，执行不被误停

> 作为用户，我关闭一个终端标签通常只是不想看了；我希望进程继续，稍后能恢复，只有显式结束才停止。

**验收**

- `⌘W`、标签关闭按钮和中键关闭只卸载视图，不 kill pty、不取消 Run、不改 Todo 状态。
- 当前项目存在「没有打开视图但仍活着的 Terminal」时，标签栏出现条件式后台入口；点击可恢复同一个 terminalId，并看到关闭期间的输出。
- 最近关闭且已经退出的终端可从同一入口重新打开记录；数据保留现有尾部上限，不承诺完整回放。
- 「结束进程…」是独立动作；它会结束 Terminal，若 Terminal 承载受管 Run，则同时按取消结算该 Run。
- 不设置「30 分钟无输出自动杀进程」；空闲不是用户授权。
- 应用退出仍按当前能力结算中断，不把重启后的新进程伪装成旧进程续活。

### US-05：从 Chat 创建任务、纯聊天或纠偏

> 作为用户，我在发送前需要知道这句话会创建任务、开始执行、只聊，还是纠偏当前 Run。

**验收**

- 草稿 Thread 的任务模式主动作明确写为「创建并派活」；一次确认创建 Todo + Run，用户原话保留在 Thread。
- 纯聊天模式主动作只是「发送」；可以产生受管对话 Run，但不得创建隐藏 Todo。
- 已有任务且 Run 活跃时主动作是「纠偏」，沿用真实投递回执。
- 已有任务且当前没有 Run 时，若发送会继续执行，主动作必须明确写为「继续并运行」；不能只用一个无法区分语义的箭头。
- 已确认任务只允许记录，不静默启动新 Run。
- 纯聊天转为任务时保留 Thread 和既有 Run 历史，不复制消息、不改写原执行时间。

### US-06：Mission 仍然是明确的任务分派

> 作为用户，我交给 Super Agent 一个目标，希望先批准计划，再由它创建和分派子任务。

**验收**

- 「开始规划」创建 Mission Todo 与 Supervisor Run。
- 只有计划审批通过才创建 child Todo / Delegation / worker Run。
- 一次计划审批就是本批 child Run 的授权，不再要求逐条重复点「派活」。
- 取消 Mission 级联停止未终态执行，但保留所有历史 Run 与原来的任务归属。

### US-07：IM、Bot、插件与命令入口遵守同一确认闸

> 作为用户，我从飞书或 Bot 发起工作时，希望任务形状与桌面一致，也不会因为通道不同而被静默开跑。

**验收**

- IM 普通消息或 `/task` 可以创建 Todo；没有明确运行授权时只进入待办 / 待指派。
- `/run`、用户明确的「开跑」指令或桌面「派活」才是 Run 授权；回执包含同一个 Todo key。
- Bot、插件、命令面板创建任务时复用同一领域动作；插件没有 `task:start` 权限时不能起 Run。
- 同一来源重复投递不能创建重复 Todo 或重复 Run。

### US-08：界面只有一个任务目录和一个视图入口

> 作为用户，我不想在左栏、项目树、标签栏看到三份口径不同的终端列表。

**验收**

- 左栏只有任务与项目；删除「终端 Agent（未绑任务）」分组和项目树里的 Terminal 子列表。
- 打开中的视图只在标签栏；隐藏但仍活着或最近结束的视图只在条件式后台 / 最近入口。
- 不在标签、图标、区域标题上增加计数、红点或彩色徽标。
- 点击任务、恢复视图、切换项目不改变任务顺序、项目展开状态或列表滚动位置。

## 4. 五种来源的统一结果

| 来源 | 用户明确动作 | 立即产出 | 是否自动进入任务 |
|---|---|---|---|
| 任务面板 | 派活 | Todo 已有 + 新 Run | 是 |
| 终端 · 打开 Agent 终端 | 选择 Agent | 探索 Run + Terminal，Todo 为空 | 否，可后关联 |
| 终端 · 手敲 pi | 用户自己输入命令 | Terminal | 否，只能关联 Terminal |
| Chat · 任务模式 | 创建并派活 / 继续并运行 | Todo + Run，或既有 Todo + 新 Run | 是 |
| Chat · 纯聊天 | 发送 | Thread + 无 Todo 的对话 Run | 否，可后转任务 |
| Super Agent | 开始规划、批准计划 | Mission + Supervisor Run；批准后 child Todo + Run | 是 |
| IM / Bot / 插件 / 命令 | 建任务、明确开跑 | Todo；授权后 Run | 建任务时是 |

## 5. 状态呈现要求

| 事实 | 左栏任务 | 标签 / 后台 | 禁止的呈现 |
|---|---|---|---|
| 无 Todo 的探索 Run 正在执行 | 不出现任务行 | 显示运行状态 | 自动新建「未命名任务」 |
| 探索 Run 关联到 Todo | 反映该 Run 的真实状态 | 沿用同一视图 | 更换 runId、重算开始时间 |
| 手动 Terminal 关联到 Todo | Todo 原状态不变；详情可见关联终端 | 标「手动终端」 | 补一条 running Run |
| ACP Run | 反映 Run 状态 | 原生对话面 | 伪造终端输出 |
| pty Run | 反映 Run 状态 | 原生终端面；对话面只给尾部摘要 | 把 pty tail 当完整对话 |
| 只关闭 Tab | 不变 | 进入后台 / 最近 | cancelled、failed 或 kill |
| 取消 / 归档 Todo | 按人的操作变化 | 历史仍可打开 | 删除 Run 或清空历史 run.todoId |

## 6. 端到端验收场景

1. **终端型派活**：建 Todo → 选 pi → 派活 → 断言一个 Todo、一个 Run、一个 Terminal 且 id 互相关联 → 关标签 → 三者状态不因关视图改变 → 恢复同一 terminalId → 停止 Run → Terminal 与 Run 都结算。
2. **探索后关联**：打开 Agent 终端 → 断言 `run.todoId = null` 且项目明确 → 关联现有 Todo → 断言 runId / startedAt / terminalId 不变 → Todo 显示真实执行状态。
3. **手动接管**：新建 shell → 输入一条测试命令 → 断言 Run 数不增加 → 关联 Todo → 断言 Run 数与 Todo 状态仍不变 → 任务详情能重新打开该 Terminal。
4. **纯聊天提升**：只聊一轮 → 断言没有隐藏 Todo → 转为任务 → 只新增一个真实 Todo，Thread 与历史 Run 保持原 id。
5. **远程授权**：IM 建任务 → 断言没有 Run → 明确回复开跑 → 只产生一个 Run，桌面与 IM 显示同一 Todo key。
6. **视觉回归**：左栏无 Terminal 重复列表；后台入口无常驻计数；任务与项目列表点击前后 `order / expanded / scrollTop` 不变；亮色与暗色各检查一次。

## 7. 非目标

- 不把所有 shell 命令自动识别成任务，不靠进程名猜测完成状态。
- 不把左栏改成会话中心，不新增 `sessions` 数据表。
- 不在本轮搬移 Chat composer、重做看板或引入第四种页面外壳。
- 不承诺应用退出后的 pty 守护、完整终端历史或跨重启进程恢复。
- 不自动清理仍在运行的进程，不用 TTL 代替用户的结束动作。
