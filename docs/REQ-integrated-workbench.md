# REQ · 场景工作台（原始需求）

> 状态：待逐条确认。先按原始想法记录，不展开实现细节；确认后再补数据模型、交互和排期。
> 关联：Mission / TODO / Terminal / Chat。

## 1. 目标

把「所有项目 + 项目内终端」收在一个**场景配置页面**里；Chat 聊完并确认后，按场景配置自动分配任务；Chat 随时能看所有进展。Mission、TODO、Terminal 尽量融合，不再各自一套页面和状态。

## 2. 原始需求

### 2.1 场景配置页面

- 针对所有打开的项目，以及项目内部打开的终端。
- 用文字即可修改。
- 管理所有进展。

### 2.2 自动分配

- 在 Chat 里聊好天，确认可以执行。
- 根据场景配置自动分配任务。

### 2.3 Chat 查看全局进展

- Chat 可以随时查看所有进展。

## 3. 两个具体场景

### 3.1 先起 Agent，再看状态

> 我现在比较懒，打开一个项目，进入终端，直接起一个 pi agent，运行，跑了一段时间，我就想看下进行的状态，能否有统一的地方看。

需要确认：

- 这种“先开终端、再起 Agent”的方式，Agent 要不要被 harness 识别成一个可管理的运行？
- 统一看状态的地方在哪里：场景配置页、Chat，还是两边都有？
- 没有绑定任务的 Agent，算不算“进展”？

### 3.2 一个任务，多个可见的 Agent

> 我有一个针对这个项目的任务，但是需要项目里面有多个 Agent 同时跑，可是我希望是开了 terminal 后再打开 pi agent 跑的方式，而不是我看不到的 agent 在执行。

需要确认：

- 这个任务用 Mission 承接，还是普通 TODO 直接拆成多个 Agent？
- 多个 Agent 是多个终端标签，还是同一个终端里分屏？
- “先开 terminal 再起 pi”的 Agent，如何和这个任务绑定？
- 任务要求多个 Agent 同时跑时，是否允许自动开多个终端？

## 4. Mission / TODO / Terminal 的融合假设

先只记录方向，不定实现：

- **Mission** 是任务的一种，不单独做一套页面。
- **TODO** 是任务列表 / 看板，Mission 也在里面。
- **Terminal** 是 Agent 实际运行的地方，任务和终端要能互相对应。
- **场景配置** 决定任务怎么分配、用哪个 Agent、怎么跑。
- **Chat** 是入口，也是查看所有进展的地方。

需要先确认的核心问题：

> 一个任务需要多个 Agent 时，是走 Mission 的“主管 + 子任务”，还是由场景配置直接并发起多个 Agent？

这决定了 Mission 和场景配置谁是编排者，不能两套同时存在。

## 5. 待逐条确认

1. 场景配置是每个项目一份，还是一个项目可以有多份？
2. “文字修改”是只写备注，还是要能直接驱动自动分配？
3. 自动分配是直接开跑，还是先给建议、人确认后再跑？
4. 一个任务多个 Agent，用 Mission 承接，还是普通 TODO 直接并行？
5. 终端里手动起的 pi，如何纳入任务和进展？
6. Chat 的“所有进展”包括哪些：所有项目、所有终端、所有运行、所有待确认？
7. 先做只读总览，还是直接做可编辑配置？
