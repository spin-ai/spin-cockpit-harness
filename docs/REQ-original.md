# 原始需求（纠正版 v3）

> 本文件替代前两版。界面结构以你给的线框为准：**导航 + TODO LIST + Chat + Terminal + 文件目录/预览** 五列；执行模型为 **project → terminal → agent**。

## 1. 界面结构（固定）

```
┌────┬────────────┬────────────┬──────────────────────────┬───────────────┐
│导航│ TODO LIST  │    Chat    │         Terminal         │ 文件目录/预览  │
│    │            │            │                          │               │
│    │ 已确认任务  │ 分派/对话   │ 任务绑定的真实终端        │ 项目树/文件/产物│
└────┴────────────┴────────────┴──────────────────────────┴───────────────┘
```

| 区域 | 必须包含 |
|---|---|
| **导航** | 最窄的一列；入口切换（工作区 / 统计 / 主机 / 设置），当前项高亮 |
| **TODO LIST** | 一条任务列表，按状态分组（待执行 / 进行中 / 待确认 / 已完成）；进行中内用 badge 区分排队 / 运行中 / 等待输入；没有列表/看板两套视图；点选任务同步 Chat 与 Terminal |
| **Chat** | 普通对话；只有输入 `@别名` 且带任务内容时才创建任务并派活；项目创建时自动生成别名，agent 也有别名 |
| **Terminal** | 最宽的主区域；任务绑定的真实 pty；支持多标签；显示 agent 输出，可直接输入 |
| **文件目录/预览** | 当前项目的文件树；文件与产物预览；点击文件在预览区打开 |

**只有一条任务列表，按状态分组**，既不是列表/看板切换，也不是两份数据：

```
TODO LIST
├── 待执行
├── 进行中       ← 排队 / 运行中 / 等待输入（等待输入置顶 + 高亮）
├── 待确认       ← 可「确认」
└── 已完成       ← 默认折叠
```

- 每个分组就是看板的一列，只是纵向排列，适配左栏宽度
- 任务确认后就地进入「已完成」分组
- 「进行中」里的等待输入必须置顶并高亮，不能看起来像正常在跑
- 点任务行 → 同步选中 Chat 与 Terminal

## 2. 核心流程

```
在 Chat 里输入 @别名 + 任务内容（普通消息不派活）
  → 生成任务草稿（出现在 TODO LIST 的待执行）
  → 在 project 下开 Terminal，启动并登录 agent
  → TODO LIST 的分组反映执行状态，Terminal 看真实进展
  → 直接输入纠偏
  → 执行完成，结果回到任务
  → 用户确认
  → 任务标记为已确认（仍在同一条 TODO LIST）
```

## 3. 需求

| # | 需求 |
|---|---|
| 1 | **固定五列**：导航 / TODO LIST / Chat / Terminal / 文件目录预览；除 Terminal 外均可折叠。 |
| 2 | **Chat 是唯一分派入口**：不通过表单、不从其他列表新建；一句话里能指定 project、agent、要做的事。 |
| 3 | **每个任务 = project → terminal → agent**：任务绑定一个项目；在项目目录下开独立 terminal；agent 是在该 terminal 中启动并登录的 CLI（pi / dsh / …）。harness 不预注册 Agent。 |
| 4 | **Terminal 是主区域**：真实 pty、多标签、可交互；默认打开当前任务的项目目录与 agent；输出就是进展。 |
| 5 | **状态分组即看板**：TODO LIST 按状态分组；行内显示 project、agent、状态、耗时；点行回到任务工作区。 |
| 6 | **文件目录/预览**：当前项目文件树；点击文件或产物在右侧预览（文本/图片/HTML 预览等）。 |
| 7 | **完成回任务**：agent 结束或主动回写后，结论 / 产物 / 退出状态回到任务。 |
| 8 | **确认即状态**：任务确认后标记「已确认」，仍留在同一条 TODO LIST；不产生第二份数据。 |
| 9 | **纠偏进运行中**：在 Terminal 输入或 Chat 注入，必须进入当前运行，不重开任务。 |
| 10 | **多任务并行**：不同 project / terminal / agent 同时跑；同一 project 允许多个 terminal。 |

## 4. 验收场景

1. Chat 里说“@project-two 把首页标题改大”（切换项目时别名自动生成）→ TODO LIST 出现任务 → Terminal 在 `spin-publish` 启动 pi（已登录）→ 任务进入「运行中」分组 → Terminal 输出实时可见 → 文件预览可看改动 → 完成后进入「待确认」→ 确认 → 就地进入「已确认」。
2. 运行中在 Terminal 直接输入纠正 → 当前 agent 回合立即收到，不另起任务。
3. 两个任务在不同项目、不同 Terminal、不同 agent 并行 → TODO LIST 分组里可切换。
4. 任务完成后不确认 → 仍为待确认；确认后标记已确认。
5. 文件树里点开产物 → 右侧预览显示内容。

## 5. 与上一版的差异

| 上一版 | 纠正版 v3 |
|---|---|
| 看板是中间主区域 | **Terminal 是主区域；看板就是 TODO 的状态分组** |
| 只有 TODO / 会话两栏 | **固定五列：导航 + TODO + Chat + Terminal + 文件预览** |
| 任务都直接进 TODO | **同一列表，确认是状态** |
| 文件/产物只在详情里 | **独立文件目录 + 预览栏** |
| Agent 列表/终端独立 | **agent 在任务 Terminal 里登录** |

## 5.1 别名规则（新增）

- 创建项目时自动生成唯一别名（如 `@project-two`），用于在 Chat 里定位该项目的 Agent。
- **主机只显示机器与可用 CLI**，不自动注册 Agent；Agent 在项目 Terminal 里启动后才出现，并带项目内唯一别名（如 `@dsh`）。
- Chat 输入框打 `@` 出现候选；只有消息里出现已存在的别名才创建任务，否则只记一条聊天。
- 项目别名 → 该项目当前会话选中的 Agent；agent 别名 → 该 Agent。

## 6. 待确认

1. **状态分组是否够用**：不再提供横向看板（当前按“分组即看板”实现）。
2. **确认是否允许撤销**（当前确认后即标记，不提供撤回）。
3. **一个任务一个 Terminal 吗**：重试是复用当前 Terminal，还是新开标签？
4. **完成判定**：以 agent 进程退出为准，还是必须由 agent 主动回写“完成 + 产物”？

## 7. 人像记忆

> 从导入的聊天记录、知识库资料和日常对话中，逐步构建一个人的画像：他本人、他身边的人、以及他们之间的关系，用来辅助决策。

**数据来源**

- 能导入聊天记录（微信、飞书、Telegram 等导出的记录），也能读入已有笔记和文档。
- 能选用知识库中已入库的资料作为抽取来源。
- 能从聊天里区分说话人：本人、对话对方、群里的其他人。
- 每条画像内容都标明来源（哪段聊天、哪份资料、哪次对话），能点回去看原文。
- 导入支持批量、可中断、可增量；重复导入不产生重复内容。
- 来源不可靠或太旧的内容降低权重，并明确标出。

**本人画像**

- 记录身份、偏好、价值观、硬约束、目标和当前处境。
- 偏好和约束要能说明什么时候成立、什么时候不再成立。
- 能回答“这个偏好或约束是怎么变过来的”，给出演变过程，而不是新旧并列。
- 新旧内容明显矛盾时标出来，不静默覆盖。
- 能按时间点回看“当时什么是真的”。

**他人画像**

- 记录与决策相关的人：家人、同事、合作方、朋友。
- 每个人至少能记：角色、与本人的关系、沟通偏好、重要日期、关键事件、当前状态。
- 同一个人有多个称呼、账号或群昵称时能合并；合并结果可人工修正。
- 能回答“这件事该找谁”“他大概率会怎么反应”“最近和他发生过什么”。

**社会关系**

- 关系有类型（家人、同事、雇佣、合作、朋友），也有强度和方向（谁影响谁、谁依赖谁）。
- 关系带时间，能表示开始、变化、疏远和结束。
- 能回答“通过谁能接触到某人”“这件事会影响到谁”。
- 群聊里的互动要和一对一区分开，不把群里的一次互动当成亲密关系。

**支持决策**

- 做决策时能给出：本人的约束与偏好、相关的人及其立场、过去类似决定和结果。
- 信息不足时明确标“未知”，不猜、不补全。
- 每条结论都能给出来源，让人自己判断可信度。

**确认与边界**

- 机器推断的内容先进入待确认，只有本人明确说“记住”或审核通过后才生效。
- 禁止每轮对话后自动推断写入。
- 涉及他人的敏感内容单独标记，默认不对外发送，例如不推到即时通信。
- 待确认可逐条确认或拒绝；拒绝也留痕，同类推断不反复打扰。
- 没有来源的推断不能提交确认。
- 能按人、按时间段、按来源删除。

## 8. 个人知识管理

- 静态资料能导入、能列出、能删除。
- 能按需检索，结果带出处，能回到原文位置。
- 只回答“材料里写了什么”，不回答“这个人怎么想”。
- 与人像记忆互不写入。
- 资料本身只读，问答不改原文。
- 可以在界面里浏览，但检索不依赖界面。

## 9. 多智能体终端

- 多个终端任务在同一窗口里并存，可切换。
- 每个任务有明确状态：进行中、待审批、完成、失败。
- 主界面用徽标展示状态，不用去翻终端输出。
- 待审批有独立面板，能直接处理。
- 用户可随时接管任意一个终端。
- 一个终端出问题不影响其他终端。
- 编排独立运行，不依赖主程序。

## 10. 即时通信

- 全天在线，桌面关闭时也能收消息。
- 接入微信、飞书、Telegram。
- 简单问题直接回答，复杂决策转给桌面上的 Agent。
- 结果、执行步骤、协议身份分开展示，不混在一起。
- 审批卡显眼，一次只问一个具体问题。
- 每次审批能追溯到它的来源记录。
- 桌面不在时明确告知并排队，不假装已经处理。
- 陌生人或未授权会话不能触发任何操作。
