# 页面优化原型

八个可直接打开的静态原型，用来说明「资料 / 记忆 / 人物 / 协作场景 / 一条 Mission 穿过四个页面」该长什么样。不是最终实现，但每个改动都对应一处具体问题。

打开方式：双击对应 HTML（无构建、无依赖）。右上 `◐` 切亮 / 暗。

| 文件 | 页面 | 主要解决的问题 |
|---|---|---|
| [`knowledge.html`](knowledge.html) | 资料（知识库） | 输入与输出被拆到两列；引用点不动；解析引擎配置占满右栏；看不到解析质量 |
| [`memory.html`](memory.html) | 记忆 | L1–L4 是内部词汇；复核队列被压在正文下；主 CTA 是「运行 Dream」；注入预览只读 |
| [`persona.html`](persona.html) | 人物（人物建模） | 只有陈述性事实，没有性格与处事；没有单一可读的人设卡；关系网与置信度缺位 |
| [`coordination-scene.html`](coordination-scene.html) | 场景（协作场景） | 场景不应只是一张执行配置表；多 Agent 协作需要拟人化舞台；办公室只是 Stage Pack 的一种 |
| [`warroom.html`](warroom.html) | 场景（作战室舞台） | 发布窗口的协作不是工位：长桌、主屏、GO / NO-GO 闸门和复盘墙才是值班的空间语言 |
| [`carrier.html`](carrier.html) | 场景（航母 · 电磁弹射） | 流水线把所有任务画成同一条传送带；航母是「多弹射位并发 + 单着舰道串行」，正好对上 worker 与 review 的真实结构 |
| [`motion-workbench.html`](motion-workbench.html) | 场景（动效工作台） | 舞台只演结果，不解释原因；动效只有三档、改完只能等下一次真实状态变化；关掉动效后看不看得懂没人验证 |
| [`bot.html`](bot.html) | Bot（会话与审计） | 主动开口的 bot 不能只有气泡：沉默 / 被频控 / 转人工要和「说过的话」平级可见；每条都要能展开「为什么说」。配置（人设 / 执行体 / 日程 / 配额）在应用的「机器人」页，不在这张原型里 |
| [`mission-route.html`](mission-route.html) | Mission 动线（三条备选） | 同一条 Mission 在任务面板 / 机器人 / 场景三处各说各话：机器人占了独立一页，任务、项目、会话分散；场景 cast 里没有的 agent 会被静默丢掉；三种动线分别把事实源放在任务 / 执行体 / Mission |

### 3D spike（实验，不属于上面七个）

| 文件 | 用途 | 依赖 |
|---|---|---|
| [`warroom-3d.html`](warroom-3d.html) | 验证「整个舞台用 three.js 做 3D」值不值得：透视房间 + 视频墙 + 3D 地球 + 操作台 + 值班席 | [`vendor/three.min.js`](vendor/three.min.js)（r149，MIT） |
| [`carrier-3d.html`](carrier-3d.html) | 航母舞台的 WebGL 3D 电影感 spike：低机位逆光、程序化舰体 / 甲板 / 舰岛 / 舰载机 / 海面，DOM 热点 + 引线 + Inspector；用来判断「电影感」是否值得进产品 | 同上（`carrier-3d.js` + `vendor/three.min.js`） |

- 两个 3D spike 共用同一份本地 three.js：classic script 放在 `vendor/`，**双击仍然能离线打开**（不用 CDN、不用构建）。
- 文字刻意留在 DOM / CanvasTexture，不交给 WebGL；亮暗两套只换调色板与灯光，几何不变。
- 参数：`?theme=light|dark` 直接定格主题；拖动 / 移动鼠标做轻微视角偏移，双击复位。`carrier-3d` 另有 `?mode=config|live`、`?seq=0..6`、`?detail=1&select=`、`?motion=calm|full|off`、`?view=gallery`；`?cam=bow|island|escort|water` 仅调试。
- 结论用途：`warroom-3d` 与 `carrier-3d` 都已合入应用（`prefs.template=warroom|carrier`）；`carrier.html` 仍是航母的信息优先 fallback。
- `carrier-3d` 的舞台只读现有 `zone / pose / tone / seat`，不新增场景字段；海面有 shader 近舷泡沫带、水线轮廓与舰岛暖光倒影，另有随行驱逐舰 / 补给舰；甲板外沿是一圈薄 catwalk，不是整块板；不再用 billboard / 平面泡沫或甲板下整块 rim 板；舰体顶/底盖与舰艏外露的 hangar 平面也已去掉，低机位不会再从甲板下露出一块灰色长方体。舰体 / 甲板 / 舰载机材质与纹理在运行时生成。3D 只换渲染层，不换调度。
- 质感来源：PMREM 环境反射（金属 / 玻璃）、假地面反射（镜像屏幕 + LED）、地面拼缝、墙面压条、桌面倒角 / 线槽 / 键盘、显示器内框 / 支架、椅子扶手 / 头枕、安全帽 + 耳麦 + 背包；`carrier-3d` 另有甲板防滑颗粒 / 系留点 / 拦阻索 / EMALS 轨道、舰体钢板缝 / 锈迹 / 水线、舰岛窗灯 / AESA / 舷号 18、舰载机面板线 / 红星 / 挂架 / 折翼。
- 已知取舍：没有 Bloom / AO / SMAA；没有贴图法线 / 粗糙度，全凭环境光 + 材质参数；人和椅子是低模；文字分三层（DOM / CanvasTexture / Sprite）。真正做到「照片级质感」需要贴图 + 后期 + 更高模，是另一档预算。

## 动效工作台的结构

```
上：舞台（办公室，四块常驻房间：经理室 / 工位区 / 茶歇区 / 会议室，加审批台、验收架）
下：时间轴（过去 15 分钟的状态变化：10 次变化 · 7 次走位，可拖动 / 回放）
右：Inspector 抽屉（默认收起，点角色打开）
    状态 → 舞台（触发 / 区域 / 姿态 / 动效）
    最近一次走位（可定位回时间轴）
    关闭动效后（reduced-motion 等价检查，找只靠动效表达的状态）
    动效参数（走位时长 / 姿态幅度 / 打字，全局即时生效）
```

三件事必须能对上：舞台上看到的位置，时间轴上能找到对应的那次状态变化，右侧能读到它的触发条件。

**尺寸与自适应**：舞台是固定的 1340×540 画布（工位 180×216 × 6、房间按像素摆好），
页面用 1440×900 设计稿决定 `zoom`（`--z = min(w/1440, h/900)`，下限 0.5、上限 2.6），
再把画布宽高按「窗口 / `--z`」反算，**铺满整个窗口** —— 窗口比 16:10 更宽时不会在左右留白。
舞台再在自己的格子里等比放大并居中（`--k = min(w/1340, h/540)`）。
用 `zoom` 而不是 `transform: scale()`，文字是重新排版的，4K / 外接屏（devicePixelRatio 2）下不糊；
1280 / 1440 / 1920 / 2200 下房间、工位、时间轴的相对位置都不变，也不会互相压。

左右两列房间共用两条横带：左列**经理室 276×190 / 茶歇区 276×164**，
右列**会议室 276×190 / 验收架 240×164**，中间**工位区 690×382**——会议室和茶歇区差不多大。
门都开在朝走道那面墙；Mission `plan_review` 时北从经理室走到会议室，
标签从「空闲」变「会议中」、投屏点亮，时间轴多一条走位。

**光照（四种时段各一页）**：顶部 tab 多了一个「光照」，一屏并排给出 `清晨 / 白天 / 黄昏 / 夜晚` 四张同一时刻的舞台
（克隆当前状态，只换光照），每张右上角写着对应的 URL（`?light=dawn|day|dusk|night`），点任意一张切回实况并固定该时段；
`?view=lights` 直接打开这一页。舞台默认跟本地时间分 `dawn / day / dusk / night`，挂钟和时间轴上的时间也是真实时间；
黄昏与夜晚点亮吊灯、台灯、落地灯和地面光斑，窗外换成夕阳 / 星空 + 月亮 + 城市亮灯，
夜晚把舞台内的表面整体压暗（只改舞台，页面保持亮色）。工具栏「光照」可强制定格，
`?clock=21:30` 固定挂钟、`?light=night` 强制时段，方便截图。

「不是所有状态变化都该走位」是核心判据：失败 / 重试 / 计划批注停在原地，只有真的换了区域才走位；
时间轴上「原地」和「走位」分开标，右侧的 a11y 检查专门找「只靠动效才看得懂」的状态。

**动效工作台的可点交互**

- 点角色 / 工位 → 右侧抽屉打开，展开「状态 → 舞台」和最近一次走位（Esc / ✕ / 「详情」收起）
- 拖动时间轴 → 舞台回到那一刻（走位按当前走位时长回放）；点历史记录 → 定位到该次变化
- `▶ 回放` 依次重放 10 次状态变化；`只看走位` 过滤掉原地变化
- 动效三档（克制 / 完整 / 关闭）+ 走位时长 / 姿态幅度 / 打字，改完立刻生效；`还原默认` 复位
- `走位路径` → 画出区域边界和各角色到目标区域的路径；`模拟 reduced-motion` → 等同关动效，看静态是否可读
- 右上 `◐` 切亮暗；带参数截图：`?view=lights`、`?theme=dark`、`?clock=21:30`、`?light=night`、`?t=300`、`?select=lin&detail=1`、`?paths=1`、`?reduced=1`、`?nowalk=1`

## 资料 / 记忆 / 人物三页共同的结构

```
左：导航 / 列表（常驻，选择不销毁上下文）
中：唯一主 surface（当前对象 + 证据）
右：复核队列置顶 → 变化 / 注入 → 辅助操作
```

这样三页学一次就够：左栏选对象，中间看内容，右栏处理「需要人判断」的事。

## 协作场景的结构

```
左：Rail（全局导航，不参与场景切换）
中：唯一主 surface = 舞台（办公室 / 作战室 / 航母 · 电磁弹射）
右：Inspector（选中的 Agent / 场景配置）
上：场景库 / 实况 / 执行配置 三个 tab
```

舞台负责空间与动作，Inspector 负责细节与操作；配置模式和实况共用一个舞台，避免「预览一个样、上线一个样」。

## 每个原型的可点交互

**资料**

- 点引用角标 `1` / `2` → 右栏对应出处高亮，可打开原页
- 点左栏资料 → 中栏切换成解析预览（页码 / 片段 / 未识别页标黄）
- 展开 `配置 / 注册自研引擎` → 端点、密钥、超时
- 勾选框控制「参与检索」的资料范围

**记忆**

- 切层级（结论 / 项目 / 事实 / 原始）→ 标题、说明、条目一起换
- `未验证观察` / `Dream 建议` 两个 tab；接受 / 拒绝后计数同步下降
- 点注入预览里的条目 → 展开「为什么被裁」
- 条目 `⋯` → 查看来源与引用 / 编辑 / 降级 / 标为过期

**人物**

- 点人物 → 换人设卡；没有卡的人给真实空态（待确认 N 条 → 去确认）
- 每节 `展开原话` → quote / 时间 / 来源
- 复核队列接受 / 拒绝后，页头与列表角标同步下降
- 人物 `⋯` → 复制注入片段 / 导出角色卡 JSON / 删除

**协作场景**

- 「场景库」→ 点「进入实况」进入办公室舞台；作战室 / 航母是两个独立舞台原型（`warroom.html`、`carrier.html`）
- 点 Agent / 工位 / 白板 / 审批托盘 / 验收架 → 右侧 Inspector 以抽屉打开
- 顶部「详情」开关 Inspector；默认收起，让舞台保持全宽
- 舞台区域：工位 / 主管 + 白板 / 审批台 / 验收架 / 机房 / 茶歇休息 / 会议协作
- 会议协作角只在宽屏显示（≥1400px），窄屏先隐藏，避免挤压工位
- 状态走位：等待 → 审批台、验收 → 验收架、空闲 → 茶歇；只在页面加载/状态变化时走一次，动效关闭时不走
- 静态截图可加 `?nowalk=1`，跳过入场走位
- 顶部「实况 / 配置」切模式：配置态显示座位编号、可编辑区、阵容、编排、呈现；空位可直接看到
- 场景库 →「新建场景」或舞台右上「派活」都有完整弹层
- 动效三档（克制 / 完整 / 关闭）；右上 `◐` 切亮暗
- 直接带参数截图：`?view=live|gallery|profile`、`?mode=config`、`?detail=1`、`?nowalk=1`、`?theme=dark`、`?select=bei`

## Bot 的结构

机器人有**两个面**，别混在一起：

| 面 | 管什么 | 在哪 |
|---|---|---|
| 配置页 | 名字、头像、职责、能力档位、绑哪个执行体、日程、配额、暂停 / 静音 | 应用 rail 上的「机器人」（和「项目」同一套骨架：概览条 + 卡片 / 列表 + 行内操作） |
| 会话（`bot.html`） | 它说过什么、为什么说、为什么没说 | 配置页「打开会话」进入；不在 rail 上单独占一格 |

`bot.html` 只画会话这一面：

```
左：bot 会话列表（不是统计面板）——人格、模式、配额都挂在 bot 上
中：回合流——主动 / 回你 是气泡；沉默 / 被拦 / 转人工 是细行，且都能展开「为什么说」
右：Inspector——人格卡 / 记忆四层 / 出场规则，切 tab 不换页
下：以 bot 身份说话（被动回复不受配额限制）
```

三个必须能对上的东西：**这句话是谁说的、它当时记得什么、它为什么现在说**。
`为什么说` 展开后固定四行：触发源、注入的记忆（带 L1–L4 标）、过闸结果、成本；
沉默与被拦同样有这四行，只是注入为空、成本写「没调用模型」——**沉默也要可审计**。

> 试过一版 Orca 式的 sidebar split（机器人列表放在工作区左栏、项目上面，两段可折叠 + 可拖分缝，
> 常量 min 88 / 120）。结论是**机器人需要一块自己的配置面**：配额、执行体绑定、日程这些是
> 「设置一次、长期生效」的东西，塞进左栏会和工作区抢高度，也和工作区的心智（任务 / 终端 / 文件）打架。
> 所以现在改成「配置页 + 会话」两分，左栏回到只服务工作区。

**可点交互**

- 点左栏 bot → 中间回合流与右栏人格卡/记忆/策略一起换（配额、口径都按 bot 隔离）
- `为什么说 / 为什么沉默 / 为什么被拦 / 为什么转人工` → 展开审计四行
- `模拟 1 小时 tick` → 按当前 bot 的配额与静音状态追加一条：正常开口 / 被配额拦 / 静音沉默
- `静音 1h` → 顶部出现静音条，再点 `模拟` 只会追加「静音中」的沉默记录
- dispatch 气泡里的 `起任务 / 先别` → 走「一句话确认 → 桌面审批」闭环：点了「起任务」只建 todo（waiting_input），不会自己起 run
- 上 `◐` 切亮暗；`?theme=light|dark`、`?bot=golo|nan|draft` 定格

`bot.html` 目前是设计原型，尚未落地；字段与规则见 [`../arch/ARCH-bot.md`](../arch/ARCH-bot.md)。

## Mission 动线的结构

`mission-route.html` 只回答一件事：**同一条 Mission 穿过任务面板 / 机器人 / 场景时，事实源放在哪。**

三条动线是三个答案，页面上半部是真实的页面（rail + PageHeader + 一个主 surface），
下半部的「原型 · 动线」条才是原型自己的东西（A/B/C、步骤、说明），不混进应用界面：

```
A 一处派单，三处同影   事实源 = 任务      Mission 只写一次库；机器人在工作区左栏（项目上面），用汇报回合里的 todo 指回，场景只画 delegation（推荐）
B 人物卡，先点人再看活 事实源 = 执行体    任务挂在人身上：点工位 / 点人格卡，打开同一张人物卡
C Mission 时间轴为中心 事实源 = Mission    左列计划、右列 delegation；左栏机器人只留一句指路
```

工作区左栏是一个 pane，三段各自可折叠：

```
TODO     范围（当前项目 / 全部项目）· 新建 · 任务分组（执行中 / 排队 / 待验收 …）
机器人   小Z（主管）+ 小A / 小B / 小C（员工，各自一条任务 T-016/17/18）；点员工，中间换成它那条会话
项目     项目列表 + 未完成数（当前项目高亮）
```

代码里的三处割裂（原型的每一屏都对应其中一条）：

- `TaskPane` 直接用 `state.todos`，Mission 子任务按 `parentId` 缩进 → 任务面板能看见
- `buildOfficeModel` 的 `members` 用 `actors.find(agentId)` 之后 `filter(Boolean)`：cast 里没有该 agent 就整条静默消失
- 机器人现在是一个独立页面（rail）；工作区左栏只有「任务 + 项目」，同一件事要跨页看 —— 本原型把它挪到项目上面
- 右栏「分配到的任务」已经是 `executorAgentId` → 任务面板同一投影，但汇报回合只带 `runId`，todo 只在 `trigger.ref` 里 → 说了「跑完了」点不回任务
- 根因是 `bot_turns.botId` 与 `todos.agentId` 两套命名空间；现在用 `bot.executorAgentId` 做映射，原型按这个字段画

**可点交互**

- 底部 `A / B / C` 换动线，`1…n` 换步骤；`上一步 / 下一步` 或 ← → 也走
- 页面里带 hover 反馈的行（Mission / 任务 / 工位 / 人物卡）都能直接往下走
- 底部右侧 `◐` 切亮暗；`?v=A|B|C&s=3&theme=light|dark` 定格，`?fold=bots,projects` 预折叠左栏某几段

`mission-route.html` 是设计原型，尚未落地。它不改字段，只改「任务、人、舞台」三者的入口关系。

## 设计约束

- 颜色、圆角、阴影全部取 `src/design-system.css` 的 token，没有一次性色值
- 一个区域最多一个 primary；低频操作进 `⋯`
- 中文正文 ≥ 11.5px，10–10.5px 只用于时间、编号、状态
- 亮色 / 暗色同构，不靠单边补丁

## 与实现的关系

## 作战室 / 航母两个 Stage Pack 的结构

两个原型和 `coordination-scene.html` 共用同一套外壳：Rail、页头、场景库 / 实况 tab、
场景工具栏、Inspector 抽屉、亮暗和 `?mode=config`。**只换舞台**：

```
作战室
  墙面：主屏（Mission plan）· 左：值班事件 · 右：发布指标
  中间：长桌 6 席 + 值班指挥（lead）
  右：发布闸门 GO / NO-GO（approval）      左：复盘墙（review）
  下：对外同步草稿（可选位）                下：静默角（idle）
  zone 映射：工位区 → 长桌 · 审批台 → 闸门 · 验收架 → 复盘墙 · 茶歇 → 静默角

航母 · 电磁弹射（参考福建舰）
  甲板：舰艏 2 条 + 斜角甲板 1 条 EMALS（CAT 1/2/3，并发 worker）· 1 条着舰道 + 3 道拦阻索（串行 review）
  舰岛：PRI-FLY 塔台（着舰排序）· 双升降机：待命位（idle）· 停机位：等放行（approval）· 舷号 18
  LSO：着舰指挥官（reviewer）
  状态机：待命 → 对位 → 通电 → 弹射 → 起飞 → 拦阻 / 复飞 → 复位
  zone 映射：工位区 → 弹射位 · 审批台 → 停机位 / 塔台放行 · 验收架 → 着舰道 · 茶歇 → 升降机
```

两个原型都用 `zoom` 整块缩放（不是 `transform: scale`）：1180×560 的设计稿在不同窗口下
按实际字号重新排版，文字不会因为小数倍缩放发虚。航母走 2.5D 写实，参考福建舰（003）：
深灰甲板、可见的舷侧与舰岛体积、舰艏 2 条 + 斜角甲板 1 条 EMALS、双升降机、三道拦阻索。
航母整块先在本地坐标里画（舰艏朝上、长宽比按 003 收窄），再整体旋转 +28° 形成参考照片的斜视 2.5D；
HUD、角色标签保持水平，不跟着转。海面用深海军蓝，叠细浪 / 涌浪 / 白浪 / 阳光碎光 / 艏浪尾流，并放两艘护航舰只作尺度参照；
甲板有非滑涂料颗粒、湿痕、胎痕、系留点、猫道格栅、安全网、红色水线、舰岛阴影和折叠翼停放机；
舰体有分片接缝、锈迹、水线藻痕，舰岛有 AESA 网格、舷窗暖光、栏杆和救生筏。

两个舞台都只读 `buildOfficeModel` 已经算出来的 `zone / pose / tone / seat`，不新增字段：

- **并发**：舰艏 2 条 + 斜角甲板 1 条弹射位，对应多个 worker 并行；
- **串行**：着舰道同一时刻只允许 1 架（3 道拦阻索），对应 review / approval 必须排队；
- **失败**：中止不走「取消」，而是复飞后重新排队（`lastRunFailed` → 复飞位）；
- **原语**：Go / NO-GO、弹射能量、甲板风、拦阻索数都只是 prefs + 只读指标，不改调度。

## 两个舞台的可点交互

- 点座位 / 飞机 / 闸门 / 复盘墙 / 塔台 / LSO → 右侧 Inspector（Esc / ✕ 收起）
- 顶部「实况 / 配置」切模式：配置态显示空位、弹射位边界和期望拓扑（作战室里期望连线压在桌面上）
- 航母底部「弹射序列」可点任一步，或点「演一遍弹射」按 待命 → 对位 → 通电 → 弹射 → 起飞 → 拦阻 → 复位 走一遍
- 顶部「新建场景」弹层：办公室 / 作战室 / 航母 · 电磁弹射（默认选中当前舞台）
- 右上 `◐` 切亮暗；带参数截图：`?view=live|gallery`、`?mode=config`、`?detail=1`、`?theme=dark`、`?select=bei|zhou`
- 航母额外支持 `?seq=0..6` 直接定格某个弹射阶段

`motion-workbench.html`、作战室 3D 与航母 3D 已落地（2026-11-14 / 15），不新增状态，也不改调度：
数据仍是 `buildOfficeModel` 已经算出来的 `zone / pose / tone / seat`。

- **舞台位置**：`OfficeLive` 的 `.stage-area` 用 `ResizeObserver` 算 `k = min(w/1340, h/540)`，
  舞台在自己的格子里等比缩放并居中；Inspector 是覆盖在舞台上的抽屉，不挤压舞台。
- **时间轴**：`OfficeLive` 在内存里保留最近 15 分钟的 `OfficeModel` 快照（只读），
  每次 actor 的 `zone / tone / pose / statusLabel` 真变化时追加一条记录；可拖动、回放、只看走位。
  首次打开页面只记录「打开之后」的变化；持久化历史环仍是后续工作。
- **动效参数外置**：`walk / amp / typing / tier` 提到 `config.prefs.motion`，检查器里改完即时生效并随场景保存。
- **reduced-motion 等价检查**：`src/office/motion.ts` 的 `a11yChecks()` 按「位置 + 姓名牌 + 气泡」
  生成检查项；`模拟 reduced-motion` 与「动效 · 关闭」都会走静态路径。
- **光照**：场景页新增「光照」tab，同一时刻并排四张舞台（清晨 / 白天 / 黄昏 / 夜晚），
  点任意一张切回实况并写回 `config.prefs.light`。
