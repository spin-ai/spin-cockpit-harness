入口总表

一个入口一张卡：从哪进、经过哪几层、人点几次、落到什么、界面长什么样。14 个能造出任务的入口，全部收敛到同一条 todo + run。
14 个造任务的入口 4 类来源

先看结论

入口多 ≠ 链路长；长短看「人点几次」，不看「经过几层」。

能真正造出任务的入口 14 个，UI 上能被点到的 9 个；其余是快捷键壳、外部消息和程序化调用。 它们全部收敛到同一套 Todo → Run：新建一律 confirmed=false、parentId=null、 kind="task"，并自动 threadForTodo() 建会话。

04带上下文：元素 / 场景 / 模板 / 插件，补字段但不动状态机

不变量与两个例外

入口收敛的成本不在「入口多」，在「有的入口偷偷改了状态」。
不变量成立范围怎么保证
新建 confirmed=false全部 23 个入口createTodo / createTodos / 各调用路径同源
parentId=null（除 Mission 子任务）全部；子任务是唯一例外Delegation 写入时显式设 parentId=mission.id
kind 默认 "task"除 E12（mission）只有 supervisor 路径带 kind="mission"
自动建会话全部threadForTodo() 在 createTodo / createTodos 内
起 run 需要人的动作E1 / E8 / E13 / E16 / E17Bot 不能自己起 run；IM 只在有 Agent 时走 send
例外 1 · E16：Bot work 档建完 todo 立刻 run。点「开跑」就是授权，因此这条路径没有第二次确认。
例外 2 · E17：IM 无可用 Agent 时落 status=queued，不是 todo。队列语义要跟「在板上等人派活」区分开。
核对方式入口、字段、行号对着 electron/main.mjs / src/components/*.tsx 逐一核过（2026-11-14），对应当前工作树；配色与圆角取 src/design-system.css 的 token，本页没有一次性色值。
和 ARCH 的关系边界与状态机以 docs/arch/ARCH-super-agent.md、ARCH-chat-thread.md 为准；本页只描述「从哪进」，不定义新字段。
