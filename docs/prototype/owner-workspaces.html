三层：两个操作面 / 一套执行面 / 一层能力

操作面BOT（角色）· 终端（代码）rail 第一组，两个工作台
执行面Todo → Run → Terminal(pty)只有一套，两个面共用
能力面记忆 · 知识 · 人物 · 视觉各自一页（复用现有页面），同时是工作台里的 tab
投影面场景只画，不调度

rail 就是这张表：BOT / 终端 │ 场景 │ 记忆 / 知识 / 人物 │ 视觉，底部 说明 / 设置。 两个工作台叫「工作台」只是文档里的类型名，nav 上不出现。

能力也不是一类：按「怎么用」分三种

治理型记忆 · 知识 · 人物各一页：左列表 / 中主面 / 右复核队列；rail 上是待办徽标
调用型视觉 · 技能 · MCP视觉有自己的验证台；其余按钮挂在对象旁，结果落回知识
配置型人格卡 · 执行体 · 审批档位一次设定；只在 BOT / 终端的建档页里改

三种都不是操作面：它们没有 owner，也不替谁「干活」，只是可查、可改、可调。

这一版改了什么

  1. 两个操作面有了短名：BOT（智能机器人）/ 终端（智能体终端）。 rail：BOT · 终端 │ 场景 │ 记忆 · 知识 · 人物 │ 视觉，底部 说明 / 设置。
  2. 四个能力页直接复用现有页面：记忆 = Memory、知识 = 资料、人物 = Persona、视觉 = 视觉解析， 都是「左列表 / 中主面 / 右复核」的原有骨架；没有返回、没有第二套入口，也不再自造「治理台」。
  3. 名字只在两处：rail 上两项，页头一个词。数据层仍是 owner（bot / project）， 不造 mode 枚举。
  4. 两个左栏同构：owner 列表（可折叠）+ 这个模式下要干的活。换 bot / 换项目只在一个地方，不再有页头 popover。
  5. run 三面同源：会话卡片 → 右栏「过程」→ 终端标签；项目里多了一条 runbar 明说「同一份状态」，可以从终端跳回会话卡片。
  6. 终端只做派活，不做发起 Mission：dock 默认收起（⌘J），和 BOT 侧同一个 send()， 但只负责「一条能直接跑的活」。要拆成计划，去 BOT 跟主管说一句——发起是「交代」，不属于执行面。
  7. Super Agent 没有自己的面：Mission 是 todos(kind=mission)，owner 是项目； 主管是 BOT 里 role=supervisor 的角色。终端需要的是它的产物，不是它的发起： 终端里有计划卡（进度 / 依赖 / 子任务）、有批准（因为批准前要对着代码看清楚）、有来源标注； 发起只有一个入口——BOT 里对主管说一句。
  8. 会话里的计划卡只指路：显示「待批准 + 去终端批准」，不放可编辑计划； 两份可编辑状态就等于两处审批。子任务落进 TODO 分组，run 仍是三面同源。
  9. 记一条是门铃，不是面：任何面都能按 ⌘⇧N，落点固定是 TODO；收集箱属于终端，入口不必属于终端。
  10. 能力在工作台里是摘要：BOT 右栏是 过程 / 记忆 / 知识 / 人物 / 技能 / 日程， 项目右栏是 文件 / Git / 预览 / 知识 / 执行体；左栏底部还有一条能力条（计数 + 一键跳到 tab）。 能力改的是「这一轮吃了什么」，不是「又一个目的地」。
  11. 视觉是一页，也是工具：页里是验证台（原图 ↔ 块，逐块确认后才写入知识）； 同一个解析也出现在预览的对象旁——两处同一个结果，不另设「工具箱」入口。

  • 同一个 pane 在另一种模式里是不是同一个意思？
  • 一个 run，能不能从会话 / TODO / 终端三处一步进去？
  • 这个能力有没有偷偷长出「左栏 + 主面 + 右栏」？
